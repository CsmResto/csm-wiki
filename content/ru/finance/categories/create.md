## Создание категории

Чтобы создать новую категорию:

1. Откройте раздел **Финансы → Категории**
2. Нажмите **+Создать**
3. Заполните поля
4. Нажмите **Сохранить**

### Поля категории

| Поле | Описание |
|------|----------|
| **Имя** | Название категории. Должно быть уникальным в рамках системы. Длина — от 3 до 50 символов |
| **Родительская категория** | Родительская категория, внутри которой будет создана новая категория |
| **Тип транзакций** | Тип транзакций, которые могут относиться к категории |
| **Комментарий** | Необязательный комментарий. Максимальная длина — 250 символов |

> ℹ️ Поля **Имя**, **Родительская категория** и **Тип транзакций** являются обязательными

### Выбор типа категории

Доступные типы:

| Тип | Назначение |
|------|------------|
| `Все` | Универсальная категория. Может содержать подкатегории и транзакции любых типов |
| `Доход` | Категория только для доходных транзакций |
| `Расход` | Категория только для расходных транзакций |

### Ограничения при выборе типа

Доступные значения поля **Тип транзакций** зависят от типа родительской категории

> ⚠️ Если родительская категория имеет тип:
>
> - **Все** — доступны типы `Все`, `Доход` и `Расход`
> - **Доход** — доступен только `Доход`
> - **Расход** — доступен только `Расход`

Если у выбранной родительской категории доступен только один тип, он будет выбран автоматически, а поле станет недоступным для изменения.

### Изменение родительской категории

При изменении родительской категории система повторно проверяет совместимость типа категории.

- если выбранный тип совместим с новым родителем — значение сохраняется;
- если несовместим — поле **Тип транзакций** очищается, после чего необходимо выбрать допустимый тип.

# Редактирование категории


## Изменение названия

Поле **Имя** доступно для редактирования как у пользовательских, так и у дефолтных категорий. При переименовании дефолтной категории изменяется только её название. Лейбл остается прежним.


## Изменение родительской категории

Категорию можно перенести в другую родительскую категорию, если их типы совместимы.

| Тип редактируемой категории | Куда можно перенести |
|-----------------------------|----------------------|
| **Доходы** | В категорию **Доходы** или **Все** |
| **Расходы** | В категорию **Расходы** или **Все** |
| **Все** | Только в категорию **Все** |

При переносе категории вместе с ней перемещаются все её дочерние категории. При этом типы дочерних категорий не изменяются.


## Изменение типа категории

У дефолтных категорий поле **Тип транзакций** недоступно для редактирования.

У пользовательских категорий поле **Тип транзакций** доступно для редактирования.

**Редактирование типа пользовательской категории**

**Доходы** → **Все**, если родительская категория имеет тип **Все**

**Расходы** → **Все**, если родительская категория имеет тип **Все**

**Все** → изменение недоступно

# Удаление категории

При нажатии кнопки **Удалить** открывается модальное окно удаления.

> ⚠️ Дефолтные категории не подлежат удалению.
>
> Удалить можно только пользовательские категории.

> ⚠️ Удаление категории — действие необратимое: категория удаляется во всех регионах и локациях.

### Категория без транзакций

Если нет транзакций, привязанных к удаляемой категории, то категория удаляется.

### Категория с транзакциями

![Создание категории](/ru/images/categories/delete-category.png)

Если есть хотя бы одна транзакция (фактическая или плановая), то система показывает предупреждение, и пользователь должен выбрать категорию-замену, в которую будут перенесены все транзакции.

После выбора замены категорию можно удалить кнопкой **Удалить**.

После удаления все транзакции, которые были связаны с удаленной категорией, получают новую категорию (ту, что выбрал пользователь), а сама категория удаляется.

> ℹ️ Категории **Main Category**, **Salary** и **Transfer** никогда не отображаются в списке категорий-замены при удалении категории.

### Категория с дочерними категориями

Если у удаляемой категории есть дочерние категории, они **не** удаляются.

После удаления родителя все дочерние автоматически «подтягиваются вверх» и получают в качестве нового родителя категорию, которой принадлежала удаляемая категория.

Структура дерева сохраняется, просто сдвигается на уровень выше.

## Cкрытие категорий

Функционал скрытия категорий позволяет исключать ненужные категории из использования на уровне конкретного региона или локации.

Скрытая категория считается неактивной для выбранного уровня:

- она не отображается в списке категорий при создании транзакции — по этой категории невозможно создать новую транзакцию
- помечается лейблом **Скрыто**

### Наследование скрытия

Если категория скрыта в регионе, она становится неактивной во всех его дочерних регионах и локациях (по наследованию).


Скрытие может наследоваться либо внутри иерархии категорий (от родителя к дочерним категориям), либо по иерархии регионов и локаций (сверху вниз).

Если скрытие унаследовано с более высокого уровня, категория недоступна для включения до снятия скрытия на уровне-источнике. При этом после снятия скрытия на вышестоящем уровне сохраняются все локальные состояния категорий, заданные до момента наследования.

> ℹ️ При наведении курсора на лейбл скрытия отображается всплывающая подсказка, если скрытие категории унаследовано с вышестоящего региона. Она поясняет пользователю причину недоступности категории.
>
> Подсказка показывается только на уровне регионов и не отображается на уровне локаций, так как управление скрытием на уровне локаций недоступно, пока скрытие включено в регионе.
