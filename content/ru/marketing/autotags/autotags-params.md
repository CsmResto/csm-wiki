## Как устроено правило варианта

Правило определяет, при каких условиях гость получает вариант автотега. Набор полей в правиле зависит от выбранного параметра.

![автотеги](/ru/images/autotags/autotags-create/autotags-create6.png)

[[delimiter rows=1]]

Обычно правило состоит из следующих элементов:

1. **Параметр** — показатель, который система рассчитывает для гостя.
2. **Оператор** — способ сравнения рассчитанного значения.
3. **Сравнить с** — значение, период, время или среднее значение по базе гостей.
4. **Математическая операция** — дополнительное изменение значения сравнения, если оно поддерживается параметром.
5. **База расчета** — период, последние заказы или все время, если параметр поддерживает выбор базы.
6. **Горизонт расчета** — количество дней или заказов, которые должны участвовать в расчете.

### Операторы сравнения

В зависимости от параметра доступны следующие операторы:

- `>` — больше;
- `<` — меньше;
- `≥` — больше или равно;
- `≤` — меньше или равно;
- `=` — равно;
- `≠` — не равно;
- **Диапазон** — значение должно находиться внутри указанного диапазона.

## База и горизонт расчета

База расчета определяет, какие данные гостя участвуют в правиле. Доступные варианты зависят от выбранного параметра.

- **Период** — используются данные за последние `N` календарных дней.
- **Заказы** — используются последние `N` чеков гостя.
- **За все время** — используется вся доступная история гостя для выбранного параметра.

Опция `За все время` доступна всегда. Если параметр рассчитывается без истории, например по текущему полю гостя, выбор базы в форме не отображается.

Для параметров, которые поддерживают только период, система не предлагает выбор количества последних заказов. Для параметров, поддерживающих обе базы, можно выбрать период **или** последние заказы.

[[info type=custom color=#E06823]]
Горизонт `За период` не может превышать 9 999 дней.
Горизонт `За последние заказы` не может превышать 99 999 заказов.
[[/info]]

### Локации и база расчета

Локации, выбранные в настройках автотега, ограничивают данные, которые участвуют в расчете. Это относится к параметрам на основе чеков, визитов, покупок, оценок и бронирований.

При сравнении со средним значением по базе гостей сама база также рассчитывается с учетом выбранных локаций, если параметр зависит от локации.

## Особенности расчета параметров

### Какие чеки участвуют в расчете

Для параметров на основе чеков система использует только подходящие записи. В базовом случае чек должен:

- Быть закрытым;
- Иметь положительную сумму;
- Иметь положительную продолжительность;
- Быть привязан к существующему столу.

Для некоторых параметров действуют дополнительные условия.

- Для группы показателей среднего чека требуется не менее 5 подходящих чеков.
- Для `Среднего чека на гостя` и `Среднего чека на гостя в час` количество гостей в чеке должно быть больше нуля.
- В исходной спецификации для показателей среднего чека дополнительно указан минимальный размер чека: более 1 000 рублей для московских локаций TL1-6 и более 50 дирхамов для локации TLD2.

[[info type=custom color=#E06823]]
Если часть исторических данных не содержит информации, необходимой для конкретного расчета, такие записи не участвуют в выборке. Система использует только данные, по которым правило можно рассчитать полностью.
[[/info]]

### Время визита

Для правила по времени визита система анализирует, сколько времени каждый подходящий визит находился внутри выбранного диапазона и вне его, после чего сравнивает средние значения. Для этого параметра используются локальные даты и время локации.

### Оценки

В расчет оценок включаются только ответы, для которых:

- Указана локация;
- Оценка получена из вопроса с включенной настройкой `Include in Guest Statistics`.

Если один ответ содержит несколько таких оценочных вопросов, сначала система рассчитывает среднюю оценку внутри ответа. Для `Средней оценки` затем рассчитывается среднее по всем подходящим ответам. Для `Последней оценки` используется самый поздний подходящий ответ.

### День рождения

Количество дней до или после дня рождения рассчитывается по календарным датам. Время суток не влияет на количество дней.

## Настройка правила по покупкам

Параметр `Купленные продукты` позволяет сегментировать гостей по приобретенным продуктам.

![автотеги](/ru/images/autotags/autotags-create/autotags-create7.png)

[[delimiter rows=1]]

Чтобы настроить правило:

1. В поле `Параметр` выберите `Купленные продукты`.
2. В поле `Сгруппировать по` выберите `Категории` или `Группы`.
3. Выберите нужные элементы в дереве продуктов.
4. Укажите оператор и количество покупок.
5. Выберите базу и горизонт расчета.
6. Если выбрана база `Заказы`, настройте поле `Как считать`.

В дереве можно выбрать:

- родительскую категорию или группу — тогда в правило автоматически входят все дочерние продукты;
- отдельные продукты внутри категории или группы.

### Как считать покупки по последним заказам

Если база расчета — `Заказы`, доступны два варианта:

- **В сумме** — условие проверяется по всей выборке последних заказов целиком. Это значение используется по умолчанию.
- **В каждом заказе** — условие должно выполняться отдельно в каждом заказе из выборки.

Например, для правила `Покупки в категории «Фирменные кальяны» ≥ 1 раз` и последних 3 заказов:

- при варианте `В сумме` достаточно, чтобы хотя бы одна такая покупка встретилась суммарно в трех заказах;
- при варианте `В каждом заказе` такая покупка должна присутствовать в каждом из трех заказов.

## Сравнение со средним по базе гостей

Для параметров, которые поддерживают сравнение со средним аналогичным показателем по базе гостей, можно использовать динамическое значение вместо фиксированного числа.

Система выполняет расчет в следующем порядке:

1. Рассчитывает значение параметра для конкретного гостя в выбранной базе и горизонте.
2. Рассчитывает среднее значение этого же параметра по базе гостей за отдельный горизонт.
3. При необходимости изменяет среднее на указанное число или процент.
4. Сравнивает значение гостя с полученным результатом.

Дополнительная математическая операция может:

- Прибавлять или вычитать фиксированное число;
- Прибавлять или вычитать процент от среднего значения. Процент математической поправки может быть больше 100%, поскольку используется как коэффициент и не ограничен диапазоном от 0 до 100.

Например, если средний чек гостя равен `3 500`, среднее по базе — `3 000`, а правило требует быть выше среднего на `20%`, значение сравнения будет равно `3 600`. В этом примере условие не выполняется.

[[info type=custom color=#E06823]]
Числовые значения сравнения не могут быть отрицательными, если поле не предусматривает математическую поправку.
[[/info]]
